Senthil.Comp

A complete 32-bit computing platform from scratch!

Introduction

Senthil.Comp is an attempt to create a complete 32-bit computing platform from scratch, purely in software. The core components of this project include:

  • Instruction Set Architecture
  • Virtual Machine
  • Assembly Language
  • High-Level Language
  • Operating System Kernel

But... Why?

Why would anyone even want to attempt something like this? Don't I have something more important... something more feasible to work on?

The Allure of the Bare Metal

I have always been fascinated by low-level programming. I started coding in Borland C++ on DOS. In that era, there was no safety net. There was no abstraction layer, no virtualization, no user-vs-kernel space, and absolutely no sandboxing. When your Borland C++ program executed, it operated with the equivalent of "Kernel/Root" privileges over the entire machine.

It became even more fascinating when I tried assembly programming. I compiled code into a raw binary blob, flashed it to a floppy disk, and booted directly from it just to print "Senthil" on the screen.

Absolutely nothing else existed in the system - I had total control! There is something incredibly neat about being able to control every single byte of data moving through a machine, managing every aspect of the system directly.

The Problem with Modern Emulation

Today, if you want that type of programming environment, you have plenty of options. There are excellent emulators for pretty much every machine or architecture imaginable.

But there is a catch. Most real-world systems come with an immense amount of quirks and historical baggage:

  • Market Pressures: Some quirks exist because a company rushed to beat a competitor to market.
  • Legacy Support: Others are there strictly for hardware limitations or backward compatibility.
  • Missing Docs: Then there is the documentation - or lack thereof. Because low-level programmers are a dying breed, the docs are rarely accessible or available in an easily consumable format.

The Insane Idea: Virtual Hardware

After years of trying repeatedly, I had the insane idea to build a complete computing stack from scratch. I won't just have complete control over the software running on the system - I will have total control over the hardware itself, because I am going to create it virtually.

But why stop at just a virtual machine and a custom assembly language? Why not keep building layers upward to see exactly how far this rabbit hole goes?

Building the Software Ecosystem

The vision is to expand this into a whole ecosystem:

  • High-Level Language: A custom language to make programming elegant.
  • Simple Runtime: I/O and memory management libraries to deploy applications faster.
  • OS Kernel: A custom operating system kernel to abstract away the virtual hardware.

Once I toss in a basic task scheduler, robust context switching, and true multi-tasking, a blank screen will transform into a living, breathing ecosystem.

The Ultimate Goal: Self-Hosting

Ultimately, this will all lead to the holy grail of system design, the ultimate litmus test for any custom architecture: self-hosting.

The grand dream is to use Senthil.Comp to run its own assembler and compiler, building the platform entirely within itself. It is a massive, incredibly ambitious mountain to climb - but hey, I can dream big, can't I?

The Journey, Documented Step-by-Step

Building a complete computing stack from scratch is bound to be a wild, chaotic ride, and I plan to document every single mile of it. I will be capturing the entire journey step-by-step in the dedicated series of posts below. Every design idea, implementation strategy, boneheaded mistake, frustrating bug, breakthrough "aha!" moment, and incremental milestone will be laid out in the open. Whether it succeeds spectacularly or crashes in a ball of virtual smoke, you will see exactly how it happened.
